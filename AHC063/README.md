# AHC063のchokudai search比較

元の`a02.cpp`のビームサーチを、1000手目までの探索を繰り返すchokudai searchへ変更した。

| ファイル | 用途 |
|---|---|
| `a02.cpp` | 削除なしの二分ヒープ版 |
| `a02-bst.cpp` | 赤黒木版。各層の上位`R`個を保持 |
| `a02-common.hpp` | 両版が共有する状態遷移、評価、探索本体、経路復元、引数処理 |
| `run-a02.sh` | ヒープ版のコンパイル、全入力の実行、CSV保存 |
| `run-a02-bst.sh` | 赤黒木版のコンパイル、全入力の実行、CSV保存 |
| `average_csv.py` | ケース番号以外の各CSV列の平均を表示 |

状態コンテナと経路木には`../structs/chokudai_search.cpp`を使用する。赤黒木は、この環境のlibstdc++で赤黒木として実装される`std::multiset`を使う。

## 探索方法

初期状態を0層目に保存し、0〜999層目を順に走査する。各層で最良の未探索状態を1つ取り出し、合法な次状態をすべて生成して次の層へ追加する。1000手目の候補を生成したら浅い層へ戻り、同じ処理を繰り返す。探索済みの状態はキューから取り出されるが、他の未探索状態は周回をまたいで残る。

- 探索の深さは常に1000手。蛇が好みの色列になった場合も、1000手目までの探索を続ける。
- 各層の展開数は1周回につき最大1個。
- `--loops R`は最大周回数。既定値は1000周回。
- 時間制限の既定値は1.9秒。1状態の展開が終わるたびに確認する。
- 赤黒木版は各層で上位`R`個を保持する。同評価値では両版とも生成が早い状態を優先する。

同じ入力と`R`を指定し、時間制限に達する前に終了すれば、両版の展開順と最終的な解が一致する。

評価式は元コードと同じ`10000 * (length + matches) - turns`で、大きいほど良い。操作の生成順は`U`、`D`、`L`、`R`。盤外移動とUターンの禁止、餌の取得、胴体を噛みちぎったときの餌の復元と一致数の更新も引き継いでいる。問題の仕様は[ahc063_a.md](ahc063_a.md)を参照。

出力する経路は、初期状態を含む0〜1000手目の全生成状態のうち、評価が最良だった状態への経路。1000手目まで探索していても、出力する操作列は1000手より短くなる場合がある。キューから削除された候補についても、最良解と経路木は別途保持する。

## 実行と集計

`AHC063/in/0000.txt`、`0001.txt`、…に入力を配置してから、リポジトリのルートで実行する。

```bash
./AHC063/run-a02.sh
./AHC063/run-a02-bst.sh

python3 AHC063/average_csv.py AHC063/out02/a02_results.csv
python3 AHC063/average_csv.py
```

スクリプトは毎回ソースをコンパイルし、4桁の番号を持つ入力をすべて実行する。既定では最大5ジョブを並列実行する。同じ回数で逐次比較する場合は、例えば次のように指定する。

```bash
MAX_JOBS=1 ./AHC063/run-a02.sh --time 60 --loops 100
MAX_JOBS=1 ./AHC063/run-a02-bst.sh --time 60 --loops 100
```

`--time`と`--loops`はC++プログラムへ渡す。時間の位置引数、`-t`、`--time=SECONDS`、`--loops=COUNT`も使用できる。

| 環境変数 | 用途と既定値 |
|---|---|
| `MAX_JOBS` | 並列数。既定5 |
| `INPUT_DIR` | 入力の保存先。既定`in` |
| `OUTPUT_DIR` | 解と標準エラーの保存先。既定`out02` / `out02-bst` |
| `OUTPUT_FILE` | CSVの保存先。既定は出力ディレクトリ内の`a02_results.csv` / `a02-bst_results.csv` |
| `CXX` | C++コンパイラ。既定`g++` |

相対パスは各実行スクリプトのある`AHC063/`から解釈する。

```bash
INPUT_DIR=/path/to/inputs ./AHC063/run-a02.sh --loops 10
```

## 保存される結果

ヒープ版は`out02/`、赤黒木版は`out02-bst/`に保存する。

- `a02_results.csv` / `a02-bst_results.csv`：全ケースの測定結果。ケース番号順。
- `out02_0000.txt` / `out02-bst_0000.txt`：出力した操作列。
- `out02_0000.stderr.txt` / `out02-bst_0000.stderr.txt`：標準エラー出力。

CSVの列はAHC059・AHC042と共通。

| 列 | 意味 |
|---|---|
| `case_number` | 入力ファイルの番号 |
| `peak_memory_kb` | `/usr/bin/time`の`%M`で測った最大RSS（KiB） |
| `total_path_length` | 出力した操作回数。標準エラーの`Total path length` |
| `final_layer_visits` | 1000手目に到達した回数。標準エラーの`Final layer visits` |

`final_layer_visits`は、999手目の状態から1000手目の候補を生成した展開を1回と数える。時間切れで1000手目まで進まなかった周回は数えない。子状態の個数や、出力した操作列の長さとは異なる。

標準エラーの先頭行には、元コードと同じく絶対スコアを`M`で整数除算した値を出す。続けて`Total path length`と`Final layer visits`を出す。

## 検証

作成時点ではAHC063の実入力が未配置のため、一時ディレクトリに生成した50入力で`--time 60 --loops 3`を実行し、両版の操作列・スコア・操作回数・到達回数が一致すること、CSVと平均集計が正しいことを確認した。出力を独立したシミュレータで再生し、移動の合法性、餌・体色の保存、スコアも検証した。

加えて、ランダムな合法手による6497状態遷移を独立したシミュレータと比較し、食事・通常移動・噛みちぎりの一致を確認した。
